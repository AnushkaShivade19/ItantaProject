# Product Requirements Document (PRD)

## 1. Executive Summary
The Agentic AI Software Development Framework is a multi-agent, autonomous software-generation ecosystem. It ingests natural-language specifications and orchestrates a pipeline of specialized AI agents to deliver a fully functional, tested, and validated software project. The framework strictly adheres to a Test-Driven Development (TDD) methodology, ensuring high engineering rigor and verifiable output.

## 2. Core Architecture
- **Backend Architecture**: FastAPI, MongoDB, PyYAML, Pytest, and the Groq Async SDK.
- **Frontend Architecture**: React 19, Tailwind CSS, Phosphor Icons, and Shadcn primitives.
- **Agent Orchestration**: LangGraph-based sequential execution of intelligent agents located in `/app/backend/agents/`.
- **Project Outputs**: Automatically generated source code, configurations, and test files are persisted in `/app/backend/output_projects/<run_id>/`.
- **Observability**: Comprehensive logging via `framework.log`, granular per-run JSONL event logs, and persistent state snapshots.

## 3. Technology Stack & Preferences
- **Primary LLM Provider**: Groq (utilizing models such as `llama-3.3-70b` for complex reasoning and `llama-3.1-8b` for rapid execution).
- **User Interface**: A comprehensive React dashboard featuring a professional, terminal-inspired aesthetic.
- **Delivery Strategy**: Strict, phased delivery with mandatory confirmation gates.
- **Scope**: Capable of full-stack generation across any standard programming language (with dynamic test runner support).
- **Export Mechanism**: Finalized projects are packaged as a downloadable ZIP archive.

## 4. Development Phases & Capabilities

### Phase 1: Project Setup
Establishes the foundational environment, directory structures, and base configurations required for the framework.

### Phase 2: Core Orchestrator
Implements the central state management and workflow routing logic, ensuring seamless handoffs between agents.

### Phase 3: Intake Agent
Parses the initial user specification. If the request is ambiguous, the Intake Agent generates targeted clarifying questions. Once resolved, it compiles a structured, formal specification.

### Phase 4: Architect & Planner
- **Architect**: Designs the system layout, database schema, and API contracts.
- **Planner**: Decomposes the architectural design into a sequence of atomic, actionable implementation tasks.

### Phase 5: QA Agent (TDD-First)
Enforces Test-Driven Development. The QA Agent iterates over planner tasks and generates failing test files (e.g., `pytest` for Python, `jest` for Javascript). 
- Tests assert behavioral requirements, cover edge cases, and utilize standard mocking libraries.
- The framework natively sandboxes these files and provides a terminal-style preview within the UI.

### Phase 6: Coder Agent
Responsible for generating production-ready implementation code to satisfy the failing tests generated by the QA Agent. The generated files map directly to the planned architectural structure.

### Phase 7: Validator & Recovery
- **Validator**: Automatically executes the test suite against the generated code. It dynamically detects the target language and invokes the correct test runner (e.g., `pytest` or `npx jest`).
- **Recovery**: If validation fails or linting issues are detected, the Recovery Agent analyzes the error output and iteratively corrects the implementation until the tests pass.

### Phase 8: End-to-End Execution
Finalizes the pipeline with a comprehensive summary report and packages the verified project for deployment or download.

## 5. Known Constraints & Ongoing Enhancements
- Certain advanced recovery capabilities are under active iteration to improve the success rate of highly complex tasks.
- API rate limiting (e.g., HTTP 429) from the LLM provider is handled gracefully via exponential backoff, which may introduce variable execution times during periods of high load.
